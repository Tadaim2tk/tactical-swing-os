# 静かな誤答の総点検（2026-08-31、ERS知見の移植監査）

ERS が 2026-08-30 に見つけた「動いているのに間違った答えを返すバグ」4種＋方法論6項
（`PROMPT_TO_TSO_2026-08-30.md` / `METHOD_TRANSFER_TO_TSO.md`）を、TSO の実コード・実データに
対して検証した記録。本文書がERSへの回答を兼ねる。

方法: 10次元×独立エージェント監査（各次元を別々の資材で2〜3回独立実行、計25+エージェント）。
全所見に実測必須（目視レビュー禁止）。主要P1は懐疑役の独立再現、または複数エージェントの
独立到達で相互確認済み。再現スクリプトは各所見の evidence に記載。

判定の凡例: **P1**=結論・採否判断が変わりうる / **P2**=数値が歪むが方向は保つ /
**済**=TSOが既に正しくやっていた。

## 1. P1 — 結論が変わりうるもの（7件）

### P1-1. USDJPY が「死んだ特徴量」— Yahoo の open 欠陥（確定・独立再現済み）

`data/raw/USDJPY.csv`（JPY=X）の open は寄値ではない: |close−open| 中央値 0.0081% に対し
close-to-close 中央値 0.2274%（28倍差）、open==close 完全一致 36/238本、**open>high 1本・
open<low 3本**（正規の寄値ではあり得ない）。market context の chg 定義 `(close-open)/open`
（`export_market_context_snapshot.py:199` / `score_market_context.py:83`）がこの open を使うため、
chg_pct_USDJPY は真の日次変動の 1/6〜1/28 に圧縮され、dollar_strength_score は恒久的に
ほぼ中立（50±0.04）。**このままでは「USDJPY は効かない変数」という誤判定が確定する**
（27.3-c の変数採否に直結。ERS旧254件へも結合済み）。対照: DXY・SPX の open は健全。

直し方: chg を同一系列の前日close基準（close-to-close, `fill_method=None`）へ。台帳は
append-only 契約なので既存列は書き換えず、新列 `chg_cc_pct_*` を明示的移行で追加。

### P1-2. ジオメトリOOS「有効(確定)」判定は検定力ほぼゼロ（3監査が独立に同結論）

7/18-8/1 窓の +0.80R（決着11件）自体は正確に再現される。しかし:

- **プラセボ実測**: 介入前（〜7/17）の連続11決着窓32本のうち **gross>0 が 50%、+0.80R以上が
  41%**。「プラス転換」という事前基準は、何も変わっていない期間内ですら約5割の確率で満たされる。
- 並べ替え検定 p=0.29〜0.41、2標本 p=0.30。ブートストラップ95%CI **[−4.9R, +6.3R]**。
- 内訳: GOLD LONG 6件 +3.88R vs それ以外5件 −3.08R。8/1 の GOLD 1件が判定符号を反転させた。
- **軸分解**: 効果は時間決済軸のみ有意（時間決済−TP1 = +0.084%/注文, t=3.23, 16勝5敗）。
  **「SL約2倍」軸は無信号**（t≈0.2、OOSでも k=1.0 が採用セルを上回る）。
- **月効果 > 介入効果**: 月別 gross R は 6月 −2.66R → 7月 −1.40R → 8月 +3.89R（幅6.55R）。
  報告された介入効果 +0.80R はこの月次変動の内側にある（ERS「切り口の差より期間の差」の再現）。

**帰結**: 8/15 の「有効(確定)」は「符号は正だが判定不能（n不足・GOLD集中・月交絡）」へ格下げが
妥当。効果の実在は否定しない（8/2以降 SLゼロは好方向）が、「確定」の統計的裏付けは無い。
7/17 の3択提示に軸分解が付いていれば選択は変わりえた（「SLのみ」は最悪の選択肢だった）。

### P1-3. 遡及採点のアンカーが「判断の22〜26時間後に確定する終値」（2監査が独立に同結論）

`score_prediction_log.py:131` は台帳date（JST朝7時の判断日）と同ラベルのバーをアンカーにする。
米先物のバーDは判断1時間後に始まり、暗号資産バーDは翌朝9時に閉まる — つまり**アンカーが
判断後の未来情報**。実測: 619行中478行が該当、判断整合アンカーとの比較で **fwd_return_1d の
符号が51%反転**（NO_TRADE 行=見送り検証の唯一の指標では51.8%）。祝日には同日バッチ内で
アンカー規約が資産間で割れる（73判断日中21日）。

さらに known-bias #9（7/17記録・未修正）が現存: 当日タッチの約定を落とす向きは中立ではなく、
**落ちる20件の平均R=+1.02（採用群の2.2倍）**。fill率 16pt 過小・疑似エクイティ 58% 過小。
`simulate_execution.py` は当日バーを含める（side="left"）ため、**同一シグナルで採点系と
執行シム系の約定判定が19件矛盾**している。

直し方: アンカーを「判断時に既知の最後のバー」（`searchsorted(side='left')−1`）へ変更し、
当日バーを結果窓に入れる。`evaluate_signal.py:209` の `>` も `>=` へ（同型）。再採点は
append_scores の keep=last で全行自動更新。

### P1-4. 執行シムの窓ズレ地雷 — 2027年2月に発火することが構造的に確定

`fetch_market.py` は raw を毎日「直近240暦日」で全上書き（git非追跡・mergeなし）。
`simulate_execution.py:85` は信号日が系列開始より前でも黙って窓の先頭バーにアンカーする。
台帳最古 2026-06-08 が窓外に落ちる **2027-02-03 頃から、6月の判断が翌年のバーで「約定」し
始める**。シミュレーション実験（rawを8/5以降に切断）: 79注文中53件で結果が変化、**符号反転の
実例あり**（GOLD filled_sl −1.0 → filled_tp1 +0.55 等）、gross −0.17R → −1.93R。

同根で **P1-4b**: `score_prediction_log.py` の append_scores は確定済み scored 行を
invalid_data で無条件上書きする。**8/19 に本番で実発生**（US10Y 16行が空欄化→翌日復元）。
「取れなかった」が「無かった」を上書きする、ERS知見#5の正反対の挙動。

直し方: (a) fetch_market を既存CSVとmerge（履歴を縮めない）、(b) simulate_row 冒頭で
`sig_date < 系列開始` を typed status（data_window_expired）で返す、(c) append_scores で
scored→invalid_data への降格を禁止（window_expired 等の typed status へ）。

### P1-5. ニュース分類の極性反転 — 本番出力の結論ラベルが実測で逆（2監査が独立に同結論）

辞書（`config/audit_dictionaries.json`）に否定・解除・比喩の扱いが無く、実測3,459見出しで
**132(行,テーマ)以上の誤袋詰め**（下限値）:

- 「deal to **end** the Iran war」（終戦）→ 'war' で geopolitical_risk・gold_safe_haven に加点
- 「fear gauge **tumbles**」（VIX急低下=リスクオン）→ 'fear' で risk_off に加点
- 「**scale back** Fed rate hike bets」（利上げ観測後退）→ 'rate hike' で hawkish に加点
- ceasefire/truce/peace 系の語は**全13カテゴリのどこにも存在しない**（停戦を拾えない）
- 'pivot' マッチ9/9件が企業のAI転換等でFedピボット0件、central_bank_dovish は62%ノイズ
- 屈折形の全滅: fears 33件・attacks/attacked 34件・missiles 7件を取りこぼし（本物の
  エスカレーション報道ほど拾えない）— 「本物を見逃し偽物を数える」構図

影響実測: 2026-07-09 の本番出力では **risk_off・geopolitical の構成材料が100%逆方向**
（イラン合意・VIX低下の日に「地政学リスク材料あり」を出力）。60日再計算で news_market_bias
ラベルが4日反転、テーマ変化8日。自動売買には未接続だが、ダッシュボード・ai_feedback・
日報の人間向け結論が逆になる。

### P1-6. ナラティブ整合の安全網が81run全て空振り（SPEC-NQ-001が一度も実データを見ていない）

`narrative_reliability.yml` は (a) 入力 `results/signals.csv` が fresh checkout に存在しない
（daily_cycle しか生成しない・gitignore）ため**約80日間、整合記録が一度も取られておらず**

P1-5 の極性誤りを統計的に検出するはずの装置が構造的に切断されていた。
（同型: 週次 audit report も gitignore された空入力を監査して毎週 ✅PASS を出している）

### P1-7. 一次データの時限消失 — 6月分は 2026-09-04 から失効開始（対応中）

## 3. TSO が既に正しくやっていたこと（ERSへの回答を兼ねる）

- **ERS#1（pct_changeのpad埋め）: 非該当**。クロス資産のwide表・pivotを一切作らない設計で、
  pct_change は単一資産系列2箇所のみ。fill差分を全10資産・2,185行で実測して差0行。
  偽ゼロ捏造は0件（chg1d==0.0 の10行は全て本物のフラットクローズと確認）。
- **ERS#3（時間境界の定数）**: 東証型の境界定数は不使用。ただし上記P2-d（cronと
  バー切替の跨ぎ）が同型の時刻問題として実在。
- 資産ごとの固有カレンダー保持・「推測で埋めない」空欄設計・鮮度の非対称開示
  （asset_date_spread_days等）・append-only+schema enforcement・「当時の記録が無い日は
  再構成しない」（lookahead禁止）— この土台は ERS 側に無い規律であり健全。
- 介入の日付記録（prompt changelog 12エントリ）・in-sample→OOSの分離という**手順**は
  正しかった。欠けていたのは検定力・探索幅の記録・月交絡の対照（本監査で判明）。
