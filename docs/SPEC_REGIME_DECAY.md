# 仕様凍結: レジーム較正と忘却 (Regime & Time Decay)

- status: **active (frozen)**
- spec_id: SPEC-RD-001
- frozen_at: 2026-06-10 (JST)
- 実装: `src/stat_guards.py` (decay関数) / `src/build_monthly_calibration.py`
- 前提仕様: SPEC-SG-001 (統計ガード)

## 1. 目的

3大課題②「レジームシフトと忘却」への対応。
過去に有効だったパターンが市場レジームの変化で無効化したことを、
人間の監査者が月次較正レポート上で検知できるようにする。

## 2. レジーム別較正

- `generate_signal.py` が出力する `regime` 列 (UPTREND / DOWNTREND / RANGE / UNKNOWN) を
  `enrich_evaluations()` で評価データへマージする。
- 月次較正レポートに「レジーム別較正」テーブルを追加する。
- レジーム別の重み変更提案も SPEC-SG-001 と同一のゲート (n>=30, p<0.05, 増加はSharpe>0.5) に従う。

## 3. 忘却 (time decay)

| 定数 | 値 | 意味 |
|---|---|---|
| `DECAY_HALF_LIFE_DAYS` | 90 | 指数減衰の半減期(日)。90日前の評価は重み0.5、180日前は0.25 |

- 全較正テーブルに以下の情報列を追加する:
  - `decayed_avg_r`: 減衰加重平均R (直近の成績ほど重い)
  - `effective_n`: 減衰後の実効サンプル数 (重みの総和)
- 減衰の年齢は **評価日(結果確定日)** で測る。日付列の優先順位:
  `evaluation_date > hit_date > date > signal_date > run_ts`

## 4. レジームシフト検知 (decay_divergence)

`average_r`(全期間)と `decayed_avg_r`(直近加重)の **符号が逆転** し、
かつ両者の絶対値が0.05を超える場合、`decay_divergence = True` とする。
これは「全期間では勝っているように見えるが直近は負けている(またはその逆)」状態であり、
レジームシフトの兆候として月次レポートに警告を表示する。

## 5. 重要な設計判断: ゲートは変更しない

SPEC-SG-001 の統計ゲートは **無加重の正確なt検定のまま凍結** する。
decay統計は判断材料の提示(情報列・警告)に限定し、ゲート判定には使用しない。
理由:
- 加重t検定は自由度の定義が曖昧になり、仕様の監査可能性を損なう
- 「ゲートは保守的に・検知は敏感に」の役割分離が安全側
- decay_divergence検出時の対応(重み凍結・格下げ等)は人間の承認事項とする

## 6. 変更手続き

半減期等の閾値変更は新spec_idの発行と本ドキュメント更新履歴への追記を必須とする。
