# GPT側プロンプト変更履歴（介入実験の記録）

日次・月次の ChatGPT スケジュールタスクのプロンプト変更をここに日付つきで記録する。
プロンプト変更は台帳（data/signal_log.csv → prediction_log_scores）で効果測定できる
**介入**である。変更日で期間を分割し、較正・勝率・R を前後比較する。
記録なしの変更は後知恵の温床になるため禁止。

## 2026-07-15 (1): 出力契約 v2 の組込み — TSO Daily Signal Log（毎日7:00）

- 内容: 10資産固定・価格単位契約表・28列固定・ランク別必須項目・signal_id 形式。
  正本は `prompts/tso_daily_signal_log.md`（PR #89, #90）
- 動機: 採点不能行の根絶（ETH/QQQ未知資産12行・NASDAQ水準取り違え6行・29列混入・
  NO_TRADE行の0埋め・欠測日）
- 評価方法: 7/16 以降の取込 reject/警告件数と scale_mismatch 発生率

## 2026-07-15 (2): 較正指示の追加 — TSO Daily Signal Log 重要方針

- 追加文言:
  - 「win_prob・expected_rは防御的に丸めない。真の主観確率を書く。過小申告も過大申告も
    同じ較正誤差として月次採点される」
  - 「遡及採点で実証済みの失敗モードを繰り返さない: (1)供給ショック直後のmomentum追随、
    (2)entry帯未到達での成行追い、(3)資産の参照系列の取り違え」
- 動機: win_prob 単位正規化（PR #91）後の較正チェックで、B級の事前 win_prob 平均 0.45 に
  対し実現勝率 0.68（5日close基準, n=25）の**系統的過小申告**を観測。
  expected_r = win_prob × RR 経由で A級判定（expected_r>=0.45）を機械的に抑制している疑い。
- 設計上の注意: 実現値 0.68 は**アンカリング防止のため本体プロンプトには書かない**
  （「較正で採点される」という事実のみ伝える）。
- 評価方法: 8/1 の月次較正で 7/16 前後に期間分割し、較正誤差（|事前-実現|）の縮小を確認。

## 2026-07-17 (4): 執行ジオメトリの試行 — TSO Daily Signal Log 重要方針

- 追加文言:
  - 「SLはentry帯から、これまでの想定の約2倍の距離に置く。リスク量はrisk_pct基準のまま」
  - 「決済は5営業日の時間決済を基本方針とする。TP1/TP2は参考目標として従来どおり記帳する」
- 動機: 保守的SL/TP執行シミュレーション(PR #97)で、方向採点+21.6Rの同じ約定群が
  記帳ジオメトリの執行では**-5.0R(SL率55%)**と判明。SL幅×entry位置×決済ポリシーの
  格子探索(`src/analyze_execution_geometry.py`, n=37決着)では:

  | entry \ SL幅k | 1.0 | 1.5 | 2.0 | 2.5 | 3.0 |
  |---|---|---|---|---|---|
  | 現状entry+TP1決済 | -3.0% | -0.9% | -0.2% | -0.5% | -0.7% |
  | 現状entry+時間決済 | +0.7% | **+2.9%** | **+2.8%** | +1.9% | +1.3% |
  | 深entry+時間決済 | +0.1% | +0.7% | +3.0% | +2.5% | +1.7% |

  (資産%換算・同一資金リスク。方向エッジの理論上限=SLなし時間決済で+2.7%)
  ロバスト領域は「SL 1.5〜2倍 × 時間決済」。SL率55%→11%、勝率40%→57%。
- **正直な注意: この探索は警報を出したのと同一データ(in-sample・1ヶ月・n=37)**。
  そのため 7/18〜8/1 の新規記帳をアウトオブサンプル検証期間とし、8/1の月次較正で
  ダッシュボード03の執行シミュレーション(下限ブラケット)がプラス転換したかで判定する。
- 適用日: 2026-07-17 保存済み(初回実行は7/18 7:00)。人間承認: 本人選択
  (選択肢: 2倍+時間決済 / SLのみ / 適用しない のうち前者を採用)。
