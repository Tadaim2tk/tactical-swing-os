## 2. 決定した設計方針

理由まで含めて確定した判断。ここを崩すと過去の検証がやり直しになる。

### 予測台帳は GPT 判断専用（8/25 確定・人間決定）
機械生成シグナルは `data/generated_signal_log.csv` へ**隔離**する。同一ファイルに混ぜない。

- **理由**: 機械の NO_TRADE 用 signal_id が GPT 取込行と完全同形式のため、朝7時のCI先回り書込により
  後続の GPT 判断が「重複」として静かに捨てられる置換経路が存在した。加えて採点・較正・執行simに
  origin フィルタが無く統計が無区別に汚染される、台帳が29→41列化して28列契約が壊れる、の2欠陥も併発。
- **却下案**: 同一台帳に origin 列で共存させる案は採らなかった（人間決定＝「別ファイルに分離」）。

### 出力解放は「断言の許可」ではなく「較正の採点ルール」で行う
ChatGPT が提案した「断言せよ・ヘッジするな」という語調指示は却下。代わりに
「防御的に丸めるな、真の主観確率を書け。較正誤差として月次採点される」を採用。

- **理由**: 語調の鋭さは採点できないが、確率較正（Brier）は TSO の主KPIで検証可能。
- **付随判断**: 実現値 0.68 をプロンプトに直接書くのは**却下**。全行がその値にアンカリングするため、
  「較正で採点される」という事実のみ伝える。

### A級のみ実売買に限定する案は不採用
「エッジがあるからA級のみ」は台帳データ（A級 n=5）では正当化できない。risk_pct 傾斜配分どおり
B級も指値限定・保有5営業日以内で実弾に含める。

- **理由**: A級は統計ガード（n≥30）に遠く及ばない。B級は +1R/5d で機能実績あり。

### 保守的執行シミュレーションは反後知恵ルール固定
曖昧な日中値動きの順序は不明なので**すべて不利側に倒す**（最悪価格約定・同足SL優先・TP1翌足以降のみ有効）。
コストは出典なしでは捏造せず、感応度提示に留める。

### 記帳は「捏造禁止・正直に隔離」
scale_mismatch（±10%超乖離）は記録を修正せず採点から隔離するのみ。
DATA_UNAVAILABLE 行も価格空欄のまま記帳し、欠測として省略しない。

### 分析の即日適用は許容、ただしOOS検証とセット
ジオメトリ介入（SL約2倍＋5営業日時間決済）は月次較正を待たず即日適用した。

- **理由**: 分析自体は10分で完結し、適用に人間承認を得れば「早さ」と「後知恵にしない規律」
  （アウトオブサンプル窓 7/18〜8/1 を切る）は両立できる、というユーザーの指摘に基づく。

### Vault との役割分担（統合しない）
「この日・このトレード」に紐づく記録は研究台帳、「いつでも引ける知識」は claude-obsidian へ。
Vault は git remote を `upstream` に改名して誤push を構造的に封じている。

### GPT実行基盤のトラブル対応順序
プロンプト修正 →（3回失敗で）駆動方式乗り換え、という段階的対応を明文化。
