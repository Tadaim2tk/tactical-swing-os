## 監査の読みを変えた箇所

### T1は「fixture修復」ではなかった

監査は「fixture更新とGPT台帳の欠損/鮮度テストが必要」と書いたが、Codexの実測どおり
**根本はCIにpytestが無いこと**だった。`pull_request` で走るworkflowは23本中1本のみ、
pytestを走らせるworkflowは0本。さらにその下に一段あって、**pytest が
`requirements.txt` に入っておらず、workflowを書いても `No module named pytest` で落ちる**
状態だった。fixtureだけ直しても次の4件も見えないままだった。

### F2は3例あった

監査が指摘したのは「部分ホライズンで早期確定」だが、同じ関数に同型が2つあった。

1. `future.empty`（バーがまだ無い）→ `outcome="no_trade"` を返す。この値は
   `FINAL_OUTCOMES` にも `OPEN_OUTCOMES` にも属さず、`has_open_latest_evaluation` が
   False を返すため**バーが届いても永久に再評価されない**
2. `df.empty`（取得失敗）→ 同上。**一時的な取得失敗だけでシグナルが恒久的に消える**
   （#146 で Codex が指摘）

早すぎる確定と、確定もされず再挑戦もされない状態。どちらも見送りの正否が測られない。

### F3は「除外をやめる」まで踏み込んだ

監査は「判断時に既知の価格でガードする」としたが、Codexの
「近さで同一性を判定する限り本物の大きな窓開けが除外され続ける」を採り、
**検査できないときに標本を落とすのをやめた**（`scale_check` に `not_checked` を残す）。
識別子ベースの判定は台帳に限月フィールドが無いため D1 待ち。

## Codexが返した指摘（2件、両方とも正しかった）

- **#145 P1**: `no_trade_correct/missed` は確定した評価なのに `evaluation_status="skipped"`
  を持つ。`skipped` を一律に評価不能とすると、正しく採点できた見送りが母集団から消え、
  NONE/NO_TRADE の提案が insufficient_samples になる
- **#146 P1**: 上記の `df.empty` 経路

## 正直に記録すべきこと: 4本が未レビューでマージされた

`wait-for-codex-review` は **20分待って無反応なら通す（fail-open）**。
2026-09-06 の #145・#148・#149・#150 は**この経路で通った**。ゲートのログには
`No Codex review within 20 min — gate passes as a no-review PR.` と出ている。

つまり **同じ緑が「レビュー済み・指摘なし」と「未レビュー」の2つを意味していた**。
これは監査T1（Actionsのsuccessをテスト成功と読み替えた）と同じ構図なので、
fail-open で通した場合は**PRにコメントを残す**ようにした（本記録と同じPR）。

fail-open 自体は廃止していない。Codex停止で全マージが詰まる方が害が大きいという
2026-08-27 の設計判断は維持する。変えたのは「どちらの緑か」を見えるようにした点だけ。
